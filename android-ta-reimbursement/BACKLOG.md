# TA Reimburse – feedback backlog for the next version

Collected feedback to implement together in the next release (after v1.3.0).
Status: **noted – not started** (waiting for the remaining feedback before building).

## 1. Duplicate bill / invoice detection (within and across projects)
- Flag the same bill uploaded more than once, **in the same claim and across all claims/projects**
  (including archived ones), so a bill can never be claimed twice.
- Today (v1.3.0): only same-claim duplicates with the same date + amount are flagged.
- Planned checks: identical file (content hash), near-identical photo of the same bill
  (perceptual image hash), same vendor + bill/invoice no., same date + amount + vendor.
- Show which claim the earlier copy is in; block submission or require an explicit
  "this is not a duplicate" confirmation with a reason (recorded in the claim history).

## 2. Detect and block AI-generated bills
- Flag and do not accept images / PDFs / files that were generated or edited with AI.
- Planned on-device checks (no internet): C2PA "Content Credentials", IPTC/XMP
  `DigitalSourceType = trainedAlgorithmicMedia`, generator / software tags in EXIF/XMP
  (e.g. AI image tools), PDF Producer/Creator metadata, plus image-forensics heuristics.
- Limitation to communicate: detection relies on markers/heuristics; a file whose metadata
  was stripped may not be detectable, so the app will flag/block what it can detect and say so.

## 3. Provenance statement on every output
- Excel, PDF (and ZIP) state clearly that the document was generated by the **TA Reimburse
  Android app** from bills uploaded and reviewed by the named user, and that no generative AI
  was used to create the document.
- Wording to confirm with the user: the app reads bills with on-device text recognition
  (a machine-learning OCR model), so the statement should say "no generative AI" rather than
  "no AI of any kind" to stay accurate.

## 4. Digital e-signature on generated documents
- Sign every generated PDF and Excel (and the ZIP) so recipients (client, approver) can trust
  the documents were produced by the app and not altered afterwards.
- Planned: per-installation signing key kept in the Android Keystore; PDF signed with an embedded
  digital signature (PAdES), Excel signed (Office XML signature) or covered by a signed manifest,
  SHA-256 fingerprints of all outputs + a short verification code/QR printed on the documents.
- Decision needed later: self-signed key (recipients see "signature valid, signer not verified by a
  certificate authority") vs. using the user's/firm's own digital signature certificate (DSC).

## 5. Read the metadata of every uploaded file (bills AND supporting documents) – "Trust check"
- Read and analyse the hidden metadata of all uploaded images, PDFs and documents, including
  supporting documents, to flag AI-generated or fake / edited invoices. Runs on the phone, offline.
- Images (EXIF / XMP / IPTC / C2PA): camera make & model vs. no camera at all, capture date vs. the
  bill date, editing software (photo editors, design tools, AI image tools), IPTC
  `DigitalSourceType` (AI-generated / composite), C2PA Content Credentials, screenshot markers,
  GPS location vs. the client location visited (if present).
- PDFs: Producer / Creator (e.g. AI tools, online "invoice generator" sites, image editors),
  creation vs. modification date, incremental updates (edited after it was created), XMP history.
- Office files: author, application, created / modified dates.
- Invoice content checks: GSTIN format + checksum validation, invoice date vs. travel period,
  same invoice number reused across different amounts / vendors.
- Output: a per-bill "Trust check" panel (what was found and why it matters), an overall risk
  level (OK / Review / High risk), AI markers → blocked, other red flags → must be acknowledged with
  a reason, summary of flagged bills before generating the statement.
- Limitation to communicate: apps like WhatsApp and screenshots remove metadata, so "no metadata"
  is not proof of a fake; findings are signals for review, not a verdict.
